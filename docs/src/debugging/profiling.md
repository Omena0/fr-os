# CPU Profiling

## Overview

The sampling profiler records what the CPU is executing at regular intervals, producing a statistical picture of where time is spent. Unlike instrumentation-based profilers, sampling is low overhead: it does not require modifying the profiled code.

## Mechanism: Hardware PMI Sampling

1. The profiler programs a hardware performance counter (e.g., instructions retired) with a large initial value (e.g., `2^32 - 10000`).
2. After 10,000 instruction retirements, the counter overflows and fires a `#PMI` (Performance Monitoring Interrupt).
3. The interrupt handler records:
   - `RIP` (instruction pointer at the moment of interrupt).
   - `RSP` (stack pointer).
   - Current PID and TID.
   - Timestamp.
   - CPU number.
4. The handler resets the counter and resumes execution.
5. The event is written to the per-CPU tracepoint ring buffer.

## Call Stack Unwinding

For each sample, the profiler also records a call stack (up to N frames). Stack unwinding uses:
- **Frame pointer unwinding** (fast): follow the `RBP` chain. Requires code compiled with `-fno-omit-frame-pointer`. The kernel always uses frame pointers.
- **DWARF CFI unwinding** (slow, more accurate): reads `.eh_frame` or `.debug_frame` sections. Used for userspace code compiled without frame pointers.

## Profiler Daemon

A userspace daemon (`profild`) collects samples from the ring buffers and aggregates them:
1. Reads `RIP` from sample.
2. Resolves `RIP` to a symbol name using the loaded kernel symbol table (`/proc/kallsyms`) or userspace shared library symbol tables.
3. Increments a histogram: `symbol → sample_count`.
4. On request: outputs a flamegraph or flat profile.

## Output Formats

### Flat Profile

```
 45.3%   sys_write          (kernel)
 18.1%   __copy_to_user     (kernel)
 10.2%   memcpy             (libc)
  8.9%   tcp_sendmsg        (kernel)
  4.5%   slab_alloc         (kernel)
```

### Flamegraph

A flamegraph stacks call frames and shows accumulated time per call path. Generated by converting samples to a collapsible SVG. Each row represents a stack frame; width represents the fraction of samples that include that frame.

## `perf_sample` Syscall Interface

```c
// Open a profiling event (instructions retired, period 10000):
struct perf_event_attr attr = {
    .type   = PERF_TYPE_HARDWARE,
    .config = PERF_COUNT_HW_INSTRUCTIONS,
    .sample_period = 10000,
    .sample_type   = PERF_SAMPLE_IP | PERF_SAMPLE_TID | PERF_SAMPLE_CALLCHAIN,
    .disabled = 1,
};
int fd = sys_perf_event_open(&attr, 0 /* current process */, -1 /* all CPUs */, -1, 0);
// Enable:
ioctl(fd, PERF_EVENT_IOC_ENABLE, 0);
// Samples appear in a mmap'd ring buffer (perf_event_mmap_page protocol).
```
